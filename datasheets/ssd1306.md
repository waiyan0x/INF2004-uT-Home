# SSD1306 four-wire SPI display

Solomon Systech specifies active-low CS, D/C low for commands and MSB-first
data sampled on rising clock edges (PDF p. 17). The board examples use SPI
mode 0 at 4 MHz, GPIO4 for CS and GPIO3 for D/C. These pins and the 100 ms
deadline are project choices. On the supplied six-pin module, leave GPIO4
physically unwired and reserved. Use GPIO7 for SCL, GPIO6 for SDA, GPIO3 for
D/C and GPIO10 for RES. Keep this module alone on the SPI bus.
[Bench wiring](../HARDWARE_ACCEPTANCE.md#ssd1306-oled-over-spi)

`AE` puts the panel to sleep and `AF` enables
display of the configured contents (pp. 28, 37). Both send one byte and receive
zero. The PDF contains 59 numbered pages plus an appendix.
[SSD1306 revision 1.1](https://cdn-shop.adafruit.com/datasheets/SSD1306.pdf)

**Cold-start prerequisite.** Verify the module is configured for four-wire SPI.
Follow the module supply and reset sequence (p. 27) and initialize the panel
for its dimensions and charge-pump configuration. For a visible on/off check,
load a known nonblank pattern first. The single-command runtime rules neither
pulse RESET nor initialize display RAM. The existing
[OLED driver](../firmware/drivers/ssd1306_spi/INTEGRATION.md) owns reset and
initialization in a configured profile. Confirm pin ownership and panel state
after releasing that profile before executing an idle-plan rule. On the supplied
six-pin panel, sending the normal setup bytes and `A5 AF` on idle left the
screen blank. Reapplying the normal profile restored visible content on the same boot.
